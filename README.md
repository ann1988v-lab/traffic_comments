# Бот комментариев под постами Telegram

Отдельный проект с управлением через Telegram и размещением на BotHost.
Личные аккаунты отправляют комментарии в ветки постов каналов. Бот находит
автоматически пересланный пост в связанном чате обсуждений и отвечает на него.
При необходимости аккаунт вступает в этот чат перед отправкой.

## Три режима

- **Последний пост** обрабатывает последнюю публикацию каждого канала один раз.
- **Несколько последних** обрабатывает выбранное число последних постов каждого
  канала. Количество задаётся отдельной кнопкой, от 1 до 100.
- **Следить за новыми** сохраняет начальную позицию при запуске и проверяет
  последующие публикации с заданным интервалом. По умолчанию каждые 60 секунд.
  После перезапуска нажми «Статус и отчёты → Продолжить», чтобы обработать
  публикации, появившиеся после последней сохранённой позиции, включая простой.

Альбом в канале считается одной публикацией. Для одного аккаунта в панели
пользователя успешный комментарий к посту сохраняется в истории и повторно
не отправляется даже из нового плана. Если исход сетевой отправки неизвестен,
пост помечается pending и требует ручной проверки.

## Размещение через GitHub и BotHost

1. Создай нового управляющего бота через `/newbot` в [@BotFather](https://t.me/BotFather).
2. Распакуй `telegram_comments_bot.zip` и загрузи содержимое в новый репозиторий
   GitHub. В корне должны быть `main.py`, `comments.py`, `delivery.py`,
   `accounts.py`, `storage.py`, `requirements.txt`, `Dockerfile` и `bothost.json`.
3. Создай отдельное подключение в BotHost и прикрепи этот репозиторий.
4. Главный файл `main.py`, команда запуска `python main.py`, Python 3.12.
   Dockerfile и bothost.json уже включены.
5. Добавь переменные окружения из таблицы, затем запусти сборку и бота.

| Переменная | Значение |
|---|---|
| BOT_TOKEN | Токен нового управляющего бота от BotFather |
| ENCRYPTION_KEY | Ключ Fernet, который выводит `python setup_key.py` |
| DATA_DIR | `/app/data` |
| TELEGRAM_API_ID | API ID для входа по номеру или импорта без JSON |
| TELEGRAM_API_HASH | Соответствующий API Hash |

Вход через JSON с app_id/app_hash позволяет передать параметры приложения
индивидуально при подключении аккаунта. OWNER_ID для этой версии не требуется.
Каждый пользователь получает свою панель в личном чате с ботом. Аккаунты,
настройки, вложения, история комментариев и задачи изолированы по Telegram ID.

Ключ шифрования сохрани для следующих обновлений. База и вложения хранятся в
`/app/data/users/TELEGRAM_ID/bot.sqlite3`. Для этого проекта используй отдельное
хранилище BotHost. Подключи аккаунты через меню нового бота. В GitHub загружай
код из архива, а секреты задавай в переменных окружения хостинга.

## Подключение аккаунта

1. Открой своего нового бота и отправь `/start`.
2. «Подключить → JSON», затем отправь JSON своего аккаунта файлом.
3. Когда бот попросит сессию, следующим сообщением отправь авторизованный
   `.session` того же аккаунта. Кнопку «Подключить» между файлами нажимать не нужно.
4. Дождись подтверждения входа и в разделе «Аккаунты» проверь галочку ✅.

Также доступны Telethon/Pyrogram SQLite-сессии, StringSession Telethon,
Auth Key + DC ID, TData ZIP и вход по номеру. В стандартном входе по номеру
понадобятся код и, при запросе, пароль 2FA. Telegram может отклонить передачу
кода через чат. При такой ошибке создай сессию локальным входом и импортируй файл.

Сессия содержит доступ к аккаунту. Загружай её только в своего доверенного
управляющего бота. Вводимые секреты проходят через Bot API и хостинг, а
сохранённые сессии шифруются ключом ENCRYPTION_KEY.

## Настройка и запуск комментариев

1. **Аккаунты** выбирает участвующие личные аккаунты. Если выбрано несколько,
   каждый оставляет свой комментарий под выбранными публикациями.
2. **Комментарий** принимает текст либо одно фото или видео с подписью.
   Вложение до 18 МБ, подпись до 1024 символов, обычный текст до 4096.
3. **Каналы** принимает ссылки по одной на строку или UTF-8 TXT файлом.
   Можно указать несколько addlist с каналами. Совпадающие каналы объединяются.
4. **Режим и настройки → Режим** переключает три режима.
5. **Последних постов** задаёт N для режима «Несколько последних».
6. **Между комментариями** задаёт паузу между действиями отправки и вступления.
7. **Проверять новые каждые…** задаёт интервал для режима наблюдения.
8. **Проверить и запустить** показывает каналы, посты, обсуждения и ошибки
   без вступлений и комментариев. Кнопка «Запустить» под планом начинает работу.

Примеры ссылок на каналы

```text
https://t.me/your_channel
@another_channel
https://t.me/addlist/folder_slug
```

Для закрытого канала аккаунт должен заранее иметь доступ к публикациям.
Ссылка-приглашение уже доступного закрытого канала также подходит.
Обычные группы из addlist отразятся в отчёте как неподходящие получатели.
Вступление в связанный чат обсуждений происходит при запуске, когда Telegram
разрешает это действие. Если требуется одобрение заявки, пост будет пропущен
с соответствующей причиной. Капчи и административные ограничения требуют
действий владельца аккаунта.

Для изменения режима или текста останови текущую задачу и создай новый план.
Настройки уже созданного плана зафиксированы. В режиме последних постов
зафиксированы и выбранные публикации. В наблюдении отслеживаются новые посты
каналов из плана.

## Статус, остановка, отчёт

«Стоп» или `/stop` останавливает задачу. «Статус и отчёты» показывает состояние
и позволяет скачать CSV или продолжить после остановки. После завершения и
остановки бот присылает итог с CSV, где есть ссылка на пост и причина ошибки.

- sent означает подтверждённый комментарий.
- failed означает отказ или ошибку. Новый план может повторно попробовать такой пост.
- pending означает неопределённый результат. Проверь его вручную.
- skipped означает, что пост уже был обработан или ожидает проверки.

Ошибка одного поста позволяет продолжить остальные. FloodWait вызывает
ожидание указанного Telegram времени на том же аккаунте. Общее ограничение
PeerFlood может прервать задачу. Вступление в чат само по себе не даёт
разрешения публиковать произвольные комментарии, соблюдай правила обсуждений.

## Локальный запуск

Открой папку проекта в PyCharm и выбери Python 3.12 или 3.13.
В существующем окружении `E:\GPT\telegram_sender\.venv` уже есть зависимости.
Для нового окружения выполни `python -m pip install -r requirements.txt`.
Запусти `configure.py`, затем `main.py` без параметров запуска.

## Проверки

`python -m unittest -v test_comments` выполняет локальные проверки выбора
постов, вступления перед отправкой, адресации комментария к нужной ветке,
сохранения истории, мониторинга, смены режимов, медиа и разделения пользователей.
Для них используются имитации ответов Telegram. Живые аккаунты и размещение
на BotHost в ходе этих проверок не использовались.

Устройство комментариев описано в [документации Telegram](https://core.telegram.org/api/discussion).
